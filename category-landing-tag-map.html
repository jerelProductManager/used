Findings

C1 · model

Copy this call site

The whole convention is one object in the bundle, applied twice — once for the tile and once for its sub-links:

trackingMetadata: { type: CLICK_REG, component: "Category Groups", label: e, labelValue: s } ← tile: label = section, value = tile trackingMetadata: { type: CLICK_REG, component: "Category Groups", label: s, labelValue: e.name } ← sub-link: label = tile, value = link

Note what makes it work: component stays fixed while the two variable parts move into label and label_value. That keeps component cardinality low — one row in a report, not one per section — and puts the detail where it can be pivoted. Every one of the gaps found on the other four surfaces is a failure to follow this shape: Used Item Condition has the grade sitting beside the tracking object, Sort By has the display text, the trade-in configurator has the condition value and the offer.

C4 · strength

Promotion tracking here is the best on the site

Every merchandising slot fires a view_promotion on render and a matching select_promotion on click, sharing promotion_id, creative_slot and promotion_position. That means slot-level click-through is computable without any joining guesswork — TOP, LIST positions 1–3, BOTTOM, SLIDER all separable.

For the Used Department specifically: the TOP spotfront banner on this page points at /a/trade-in/64435 and is fully tracked on both impression and click. Together with the listing page's HERO banner to the same destination, the PDP's Trade In - Learn More, and the footer link, that is four measurable entry points into the trade-in funnel across the catalog surfaces. The entry-point breakdown is more complete than the impact framework assumes.

C2 · gap

Banner components don't say which banner

Category Banner and chatBanner both fire with empty label and label_value. On this page the category banner is a Hasselblad brand unit; on the next category it will be someone else, and the events are indistinguishable. Since Explora banner on the same page proves the pattern — it carries the full article title in label — this is inconsistency within a single template rather than a missing capability.

C3 · naming

One section reports under its internal key

The rail headed "What would you like to shoot?" sends label: "Applications". The other two sections send their visible headings verbatim. It's a small thing, but it means anyone reading a GA4 report has to know the internal taxonomy to recognise a section that shoppers see by a different name — and it hints that the label is being pulled from a config key rather than the rendered heading, which is worth confirming before the same pattern spreads.

C5 · cardinality

A component name built by string concatenation

The bundle contains the literal "Shop " — with a trailing space — used as a component value and concatenated with a brand name. That produces Shop Nikon, Shop Canon, Shop Sony and so on as distinct components, which is the opposite of the discipline shown by Category Groups. The brand belongs in label; the component should stay Shop Brand. Left alone, it turns a clean component dimension into an unbounded list.

Related, and consistent with what the earlier audits found: the trade-in footer link fires footer_clicks while the banner above it fires select_promotion. Any complete count of trade-in entries has to union three event families across the site.

Declared but not observed

Components the category template registers that didn't fire on the Photography landing — mostly because this category doesn't render those modules. QA candidates rather than confirmed gaps.
