Nothing in the GA4 payload says this product is used.

page_type is productDetail, identical to a new PDP. The items[] array carries no item_category, no item_variant, no condition. The only marker that this is a used unit is the -USE suffix on the SKU string — a substring match, not a dimension. Meanwhile the Google Ads tag on the very same page load sends ecomm_pcat: ["BH Photo", "Used Department", "Photography", …]. The classification exists, is computed, and is transmitted — to the ad platform, not to the analytics property the Used Department reports from.

Findings

U1 · critical

Used inventory has no dimension in GA4

To report used-versus-new performance today, an analyst has to string-match -USE against item_id or detail_page_sku. That works until it doesn't: it can't be used as a GA4 audience dimension without a custom definition, it silently misses open-box and demo inventory that carries different suffixes, and every report that forgets the filter quietly blends used revenue into new.

The frustrating part is that the app already knows. The bundle sets a global used mode from the product payload:

useEffect(() => { product && store.setUsedMode(Boolean(product.conditionFlags?.isUsed)) }, [product])

conditionFlags.isUsed is a boolean available at every tracking call site on the page. It drives the UI. It never becomes a parameter.

U2 · critical

The condition grade is one variable away from being tracked

Clicking the condition line fires detail_page_clicks / Used Item Condition with an empty label and an empty label_value. In the source, the tracking metadata and the grade string sit inside the same JSX expression — the grade is the sibling of the object that would carry it:

onClick: m, "data-selenium": "usedItemCondition", trackingMetadata: { type: CLICK_REG, component: "Used Item Condition" }, children: ["Condition:", <Icon/>, g] ← g is the grade, e.g. "9 Minor surface marks"

Adding label_value: g would give you condition mix by category, the click-through rate on the rating explainer by grade, and — once paired with add-to-cart — whether grade 8 units convert differently from grade 9s. That last question is the one that decides how aggressively the department should price by grade, and it is currently unanswerable.

U4 · consistency

Other Buying Options behaves differently on each surface

Same component name, two implementations. On the category listing it fires label: "Used" with label_value: "1910936-REG" — the SKU. Here on the used PDP it fires label: "New" with no label_value at all.

So the new → used direction is measurable per SKU and the used → new direction is only countable in aggregate. Since these two are the same behavioral question asked from opposite ends — how often does a shopper cross between conditions, and on what products — the asymmetry makes the round trip impossible to analyze as one funnel. Adding label_value to the PDP side is a one-line change that closes it.

U5 · ecommerce

items[] omits the GA4 standard fields

The array sends item_id, item_code, price, stock_status, shipping_message and store_pickup_message. It does not send item_name, item_brand, item_category or item_variant — none of those field names appears anywhere in the bundle. Three of the four B&H already has on the page, and item_variant is the field GA4's own ecommerce model reserves for exactly this kind of distinction. Populating item_variant with the condition grade would make used performance visible in every standard ecommerce report without a single custom dimension.

U6 · what works

Four things are already right

  • detail_page_sku rides on every event including view_promotion and breadcrumbs — better SKU coverage than the listing page manages.
  • Used Item Condition exists as a distinct component, so the hook for the grade is already in place.
  • breadcrumbs sends "Used Department" as a value.
  • Trade In - Learn More fires here too, so the used PDP → trade-in loop is measurable on both new and used pages.
U7 · smaller gaps

Untagged on this page

Share, Print, the 90-Second Intro video badge, the "Used Savings $161.05" figure and the warranty line all fire nothing. The savings figure is the most interesting of these — it is the used value proposition rendered as a number, and no event records whether shoppers engage with it. The searchDropdown event also fires without saying which scope was selected, even though this page pre-sets it to "Used".

The four parameters that would fix this

Each already exists in the page's own state. None requires a new event — only additional fields on events that already fire.

item_variant from conditionFlags → grade

Condition grade on view_item and add_to_cart. Makes used performance visible in standard ecommerce reports.

item_category from ecomm_pcat, already computed

"Used Department" as a real dimension rather than a SKU-suffix match. The value is already being sent to Google Ads.

label_value on Used Item Condition

The grade the shopper clicked. Currently the sibling variable of the tracking object.

label_value on Other Buying Options

The target SKU, matching how the same component already behaves on the listing page.
